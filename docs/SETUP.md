## 2. 先确定兼容组合，再安装

目前没有足够信息直接锁定整套系统的 OS、ROS 和 Python 版本。候选是为本项目单独建立 Linux 开发环境，优先评估 **Ubuntu 22.04 + ROS 2 Humble**；依据是 Unitree ROS 2 官方 README 推荐该组合。它尚未通过 X5 与交付 Go2-W 的联合兼容验证，属于候选路线。

真正安装前确认三件事即可：

1. 交付 Go2-W 使用的 SDK / ROS 包、分支或提交；高层运动服务是否可用。
2. X5 具体版本及交付 SDK 所需的 Linux、Python、CPU 架构；预编译库是否匹配本机环境。
3. 小组已有开发环境、相机型号、板载计算机及其系统；优先与可复用的交付环境对齐。

**无需服务器即可先完成仓库维护、文档学习及后续本机编译/离线数据实验。** 如后续方案需要连接服务器、远程 GPU 或部署到服务器，应先向用户说明目的、拟执行内容及本机替代方案，再进入该步骤。GitHub 代码托管不代表项目运行必须依赖服务器。

## 3. 后续可以在本机做的工作

以下为待执行路线，不是已通过的安装步骤；本轮没有下载安装包或修改系统设置。

| 顺序 | 工作 | 可检查的结果 |
| --- | --- | --- |
| A | 根据兼容信息确定独立 Linux 环境与 ROS 版本 | 记录 OS、架构、ROS、Python，避免混用既有项目环境 |
| B | 安装基础构建依赖及选定的 ROS 2 | 能运行本地 ROS 2 发布/订阅示例，记录版本 |
| C | 将厂商仓库放入本地依赖目录，固定提交 | 能在无真机网络的配置下编译消息/SDK；不运行运动例程 |
| D | 验证可脱离硬件的 X5 运动学计算与模型显示 | 先确认库能够加载、模型版本吻合，再检查正逆解一致性 |
| E | 接入离线图像、点云或录包 | 能显示输入、坐标系与时间戳；无数据时使用明确标记的示例数据 |
| F | 接入分割、代价地图或抓取的最小演示 | 形成可复现命令、输入来源、输出和一次简短日志 |

WSL 可作为本机 Linux 候选，但本次尚未验证 ROS 图形显示、GPU、DDS 多播及 USB/CAN 支持。离线学习环境能跑，不意味着同一配置已经适合真机通信。

本仓库后续只维护自己的代码、配置模板和依赖版本记录；不把整个 SDK、虚拟环境或模型权重复制进 Git。
